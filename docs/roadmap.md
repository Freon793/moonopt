# 技术路线图

本文件定义各**里程碑与完成标准**：每个里程碑只有在其“完成标准”全部满足后才算结束，
未达成时不允许把相应能力写进 README 的承诺面。

## 里程碑总览

| 里程碑 | 主题 | 状态 |
| --- | --- | --- |
| M1 | 基础层与模型层：`core`、`model`、`oracle`、公开入口、CLI 与示例 | **已完成** |

## M1 · 基础层与模型层（已完成）

**交付物**

- `core`：容差比较（`approx_eq` / `approx_zero` / `approx_positive`）、Neumaier 补偿求和、
  CSC 稀疏矩阵（构造排序/合并/丢结构零、按列访问、转置、稠密化、矩阵向量乘）；
- `model`：变量（上下界、整数标记）、线性表达式、约束（`≤` / `≥` / `=`）、目标（min/max）、模型校验；
- `oracle`：稠密两阶段单纯形参考实现（人工变量 Phase I、Bland 防循环、负右端项正规化）；
- `moonopt`：`solve` / `solve_with`、`SolveStatus`、`Solution`、`SolveOptions`；
- CLI（`moon run cmd/main`）与两个可运行示例。

**完成标准**

- `moon check --deny-warn` 与 `moon test --deny-warn` 全绿；
- `moon fmt` 与 `moon info` 之后 `git diff --exit-code` 为空；
- `moon test --target wasm-gc|js|native` 全绿；
- 能力边界在 README 中如实标注，越界调用返回 `NotSolved` + 原因。

## M2 · 标准模型输入（已完成）

**交付物**

- `format`：MPS（free / fixed）读取器与写出器；LP 格式读写；
- 模型 ↔ 文件互转；解析错误定位到行列号与具体 token；
- `cmd/parse` 巡检 CLI 与 `bench/` 的下载/报告脚本，使 `format` 可以直接吃真实实例。

**完成标准与实际结果**

- 自造 MPS / LP 样本 读→写→读 幂等：✅ 写入的文本再次写出逐字节相同；
- 真实实例解析成功率统计：✅ MIPLIB 2017 的 33 个实例全部解析成功
  （合计 173 934 变量 / 44 480 约束 / 1 651 814 非零元，最大实例 `fast0507`），
  报告见 [`../bench/parse-report.md`](../bench/parse-report.md)；
- 畸形输入只报错不 panic，且错误信息包含位置：✅ 每条 `ParseIssue` 带行号、列号与 token，
  9 个畸形用例逐条断言了位置与原因。

**过程中被真实数据纠正的两点**

- 额外 `N` 行是 MPS 的 free row，系数应忽略而不是报错（`dsbmip` 触发）；
- 真实文件的布局差异（`1.5D+02` 指数、粘连表达式、`free`/`infinity` 写法）都需要显式支持。

## M3 · 稀疏求解内核（进行中）

**已完成**

- `simplex`：稀疏 CSC 列存储 + 稠密基逆（乘积形式更新 + 周期性重新分解）、
  Phase I/II、Dantzig 定价与停滞时切换 Bland 规则、Harris 两遍比值检验、
  对偶值与检验数、人工变量驱逐、声明最优前的**按行缩放残差自检**；
- 模型侧变换：非零下界平移、自由变量拆分、有限上界行、目标常数记录；
- `SimplexOptions::relaxed()`（LP 松弛）与 CLI 求解开关；
- 差分测试：200 个随机 LP + 41 个非整数系数实例与 `oracle` 一致（状态 / 目标值 / 可行性）；
- **性能（先测量后修改）**：定价与方向计算改为无分配的 CSC 原始数组遍历；人工变量驱逐改为
  按列非零元计算单个表元素（不再为每个候选列构造完整方向）；基准改用 native release 目标
  （实测比默认 wasm 目标快 6.4×）；
- 求解报告：MIPLIB 2017 上 **14 个实例求到最优**、18 个超规模跳过、1 个数值失败（如实记录），
  14 项松弛值全部 ≤ 官方最优值（外部交叉校验，0 违反）。

**待完成**

- **稀疏基分解（LU + eta 更新）**：当前稠密 `m×m` 基逆是规模与性能的实际瓶颈
  （见 README 能力表的行数上限）；
- **对偶单纯形热启动**：为割后重优化与重解准备；
- **DeVex 定价**：当前只有 Dantzig + Bland；
- **presolve / postsolve**：空行/列、singleton、系数强化、对偶固定、界收紧与解还原；
- 数值稳健性：把求解报告中 noswot 的数值失败（缩放负值 2.0e-4）做成回归用例并修掉；
- 性能：`direction` 仍为 O(m·nnz_col)，真正的解法是稀疏 LU 基分解。

**完成标准**

- 与 `oracle` 的差分测试一致：**已满足**（随机 LP 生成器 + 已知最优小实例）；
- presolve 前后目标值一致、postsolve 还原解可通过可行性检查：待 presolve 落地；
- 公开基准批量报告（含未解出实例的诚实统计与原因）：**已生成**
  [`../bench/solve-report.md`](../bench/solve-report.md)，并将随规模上限提升继续更新。

## M4 · 证书与独立校验器

**交付物**

- `verify`：独立于求解路径的校验器 —— 原始可行性、对偶可行性、互补松弛、对偶间隙；
- Farkas 不可行证书；无界射线 + 可行起点；
- 证书序列化（JSON）与 CLI `verify` 子命令。

**完成标准**

- 故意注入错解的测试必须被拒（含数值上“看起来对”的错解）；
- 校验器不复用求解器内部中间量（代码审查可验证）；
- 不可行 / 无界实例的证书在独立实现上复核通过。

---

## M5 · 整数规划（受范围闸门约束）

**交付物**

- `mip`：分支定界（best-bound / DFS 混合、伪成本分支、受限强分支）；
- MIR / Gomory 割、取整启发式、cutoff 传播、gap 与节点报告。

**范围闸门**

> 只有 M3 与 M4 的完成标准全部满足后才进入 M5；否则本轮把资源全部投入数值稳定性、
> 文档与基准报告，M5 推迟到下一版本，并在 README 的非目标中显式标注。

**完成标准**

- 小规模整数实例求到公开已知最优值；
- 上限节点数 / 超时下返回明确的过程状态，不返回未证明的解；
- 分支过程中的每次 LP 重解都经过 `verify` 校验。

## 明确不做（非目标）

以下内容在可预见版本内不做，并会在 README 与文档中明确标注，避免夸大承诺：

- 非线性 / 凸优化（NLP）、半定规划；
- 随机规划与分解算法（Benders、Lagrangian 松弛）；
- 并行 / 多线程求解；
- 网络单纯形专用高速路径（不追求大规模网络流实例的顶尖性能）；
- MPS 的极小众扩展（完整 `MARKER` / `SOS` 语义）与 CPLEX LP 格式的全部扩展；
- Python / JS 绑定（保持纯 MoonBit、零 FFI）。

## 规模承诺的措辞

不写“目标万级约束/变量”。对外只报告**实测**：以 Netlib 实例规模分布为参照，
列出“≤ 2 000 行实例 X/Y 解到已知最优”，更大实例逐条给出结果与原因。
