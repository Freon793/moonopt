## M1 · 基础层与模型层（已完成）

**交付物**

- `core`：容差比较（`approx_eq` / `approx_zero` / `approx_positive`）、Neumaier 补偿求和、
  CSC 稀疏矩阵（构造排序/合并/丢结构零、按列访问、转置、稠密化、矩阵向量乘）；
- `model`：变量（上下界、整数标记）、线性表达式、约束（`≤` / `≥` / `=`）、目标（min/max）、模型校验；
- `oracle`：稠密两阶段单纯形参考实现（人工变量 Phase I、Bland 防循环、负右端项正规化）；
- `moonopt`：`solve` / `solve_with`、`SolveStatus`、`Solution`、`SolveOptions`；
- CLI（`moon run cmd/main`）与两个可运行示例。

**完成标准**

- `moon check --deny-warn` 与 `moon test --deny-warn` 全绿；
- `moon fmt` 与 `moon info` 之后 `git diff --exit-code` 为空；
- `moon test --target wasm-gc|js|native` 全绿；
- 能力边界在 README 中如实标注，越界调用返回 `NotSolved` + 原因。

## M2 · 标准模型输入（已完成）

**交付物**

**完成标准与实际结果**

## M3 · 稀疏求解内核（进行中）

**已完成**

- `simplex`：稀疏 CSC 列存储 + **稀疏 LU 基分解**（`P·B = L·U`，乘积形式 eta 更新 + 周期性重新分解）、
  Phase I/II、Dantzig 定价与**固定窗口**停滞切换 Bland 规则（`SimplexOptions::stall_window`，
  见"超大实例的 Phase I"一节：窗口按枢轴计、不随 m 增长）、
  Harris 两遍比值检验（带可行性守卫）、
  对偶值与检验数、人工变量驱逐、声明最优前的**按行缩放残差自检**；
- 模型侧变换：非零下界平移、自由变量拆分、**有限上界走列界**（只有"自由变量 + 有限上界"这种
  两个列之差才留成行）、目标常数记录；
- `SimplexOptions::relaxed()`（LP 松弛）与 CLI 求解开关；
- **没有产出的运行不打印目标**：`cmd/parse` 只在 `optimal` 时打印目标，其余状态印 `-`；
  内核把 Phase I 的实测人工和写进迭代上限消息。这条口径修复的来龙去脉见
  "超大实例的 Phase I"——此前正是"打印化简的目标常数"把一次正常收敛的 Phase I 读成了停滞；
- 差分测试：200 个随机 LP + 41 个非整数系数实例与 `oracle` 一致（状态 / 目标值 / 可行性）；
- **性能（先测量后修改）**：定价与方向计算改为无分配的 CSC 原始数组遍历；人工变量驱逐改为
  按列非零元计算单个表元素（不再为每个候选列构造完整方向）；基准改用 native release 目标
  （实测比默认 wasm 目标快 6.4×）；
- 求解报告（**1000 行口径、带 presolve**、全清单）：稀疏 LU 落地后 **`refused` 归零** ——
  不再有实例因规模上限被拒；`30n20b8`（presolve 后 11591 行）**16 秒求到最优**并进入对拍表，
  目标值与稠密基逆时代的 `1.5664076455872395` 相差 1.3e-10（两套后端交叉印证）；
  `fast0507`（内核 489 行）不再被拒绝、能跑，Phase I 已经跑完，Phase II 未在 1200 次迭代内收敛 ——
  它**不是停滞**，真正的原因与量级见下；报告脚本带 `-MaxIterations` 参数，本轮核实用 1200 作上限，
  因此 `danoint` / `mod010` / `bienst1` / `bienst2` 显示为 `iteration-limit`（这是报告的上限，
  不是内核的限制：它们在默认 20000 上限下可解 —— 已单独实测 `danoint`
  **3716 次枢轴 / 11.7 秒求到最优**，`obj = 62.6372804184694`，重建解在原模型上可行）；16 个重建解全部通过"原模型 行 / 界 / 目标值"
  三项检查，16 项松弛值全部 ≤ MIPLIB 官方最优值（外部交叉校验，**0 违反**）；
  报告脚本在任何重建检查失败时拒写报告；
- **规模门禁（曾经的崩溃防线，现在口径已改）**：内核过去在分配稠密基逆**之前**检查行数，
  超过 `max_kernel_rows` 即返回 `SimplexStatus::TooLarge` 并附带实测数字 ——
  触发它的真实例子是 `fast0507`（内核 63516 行 / 稠密基逆约 30.8 GB，此前在 native 上以
  访问冲突 exit `0xC0000005` 退出并拖垮整机）。**改用稀疏 LU 后内存是 `O(nnz+fill)`**，
  默认上限抬到 200000，保护分配的责任转给 `max_factor_entries` 填充预算；
  再后来上界不再占行，同一实例的内核规模是 **489 行** —— 这道门禁如今防的是"跑不完的运行"，
  而不是分配；"拒绝而非分配"的单元测试仍然保留（现在用"自由变量 + 有限上界"造行数）；
- **报告脚本的失败纪律**：`bench/report-solve.ps1` 在内核退出码非零、
  或覆盖的实例数与清单不符时**拒绝写报告**（此前一次崩溃被写成"22/33 实例成功"的报告）；
  同时修正 `solve=` 列的解析与清单里重复的 `danoint` 一行。
- **比值检验的可行性守卫**：Harris 第二遍按数值偏好选主元行后，先模拟这一步，
  若任何基本变量会被推出可行性下限（`-tol·(1+|xb|)`）则退回严格最小比值行。
  修复前 `noswot` 在 500 次迭代后以缩放负值 4.2e-4 报数值失败（超调量 = 带宽 × 主元元素，
  在比值与元素都在 1e5 量级的实例上被放大）；修复后 `noswot` 求到最优 `obj = -43.0`
  （官方 MIP 最优值 `-41.00000885`，松弛值更小，方向一致），
  300 行口径为 **15 optimal / 17 skipped / 0 其他**（该结果尚未重新生成报告文件）；
- **稀疏基分解：LU + 乘积形式 eta 更新**
  （旧的崩溃线描述保留在此处仅作背景：内核当时在分配稠密基逆**之前**检查行数，
  超过 `max_kernel_rows` 即返回 `SimplexStatus::TooLarge`。触发它是 `fast0507` ——
  内核 63516 行 / 约 30.8 GB，在 native 上曾以访问冲突 exit `0xC0000005` 退出并拖垮整机。
  稀疏 LU 落地后内存是 `O(nnz+fill)`，这条门禁默认值抬到 200000，
  保护分配的责任转给 `max_factor_entries` 填充预算；"拒绝而非分配"的测试仍然保留）；
- **报告脚本的失败纪律**：`bench/report-solve.ps1` 在内核退出码非零、
  或覆盖的实例数与清单不符时**拒绝写报告**（此前一次崩溃被写成"22/33 实例成功"的报告）；
  同时修正 `solve=` 列的解析与清单里重复的 `danoint` 一行。

- **数值健壮性：退化扰动（根因）+ 枢轴稳定性校验 + 失败恢复（三道防线）**。
  **先测量**：noswot 的系数幅度是 0.25–21（跨度比 84，中位数 1），良态 ⇒ 病态尺度不是病根，
  行列均衡被测量否掉（没有为此写任何不会被用到的代码）；真正的病根是**退化**（presolve 收紧界后
  大量基本值为 0，比值检验面对平局无从选择，成串退化枢轴让基漂移到近奇异）。
  **扰动**（`degeneracy_perturbation`，默认 1e-12）按确定性模式给求解用的右端项加 `ε·(1+|bᵢ|)`；
  残差自检始终对**未扰动**右端项测量。默认值 1e-12 是测出来的：1e-9 能修 noswot 但越过测试断言的
  1e-9 相对精度，1e-12 下 noswot **158 次迭代直达最优、不再触发恢复**且精度断言全数成立。
  另两道通用防线：**枢轴稳定性校验**（`pivot_relative_tolerance`，默认 1e-8）在选出的主元小于
  方向最大元的该比例时先重建基逆、重做比值检验；**失败恢复**（`start_with_bland`）在一次数值失败后
  从初始基重启一次，改用 Bland 规则并缩短重新分解间隔，结果同样过残差自检，仍失败则返回原始失败。
  两道防线在 300 行口径全量清单上**零回归**（15 最优、17 跳过，目标值与迭代数与改动前逐位相同，
  说明校验在这些实例上不触发）；有了扰动之后 noswot 已不需要它们中的任何一个；
- **稀疏基分解（LU + 乘积形式 eta 更新，M3 的规模杠杆）**：基不再求逆，而是左看式稀疏 LU
  （`P·B = L·U`，行主元按列内最大元选、阈值**相对**该列量级），`B x = b` 与 `Bᵀ y = c`
  各走一次三角求解；内存由 `O(m²)` 变成 `O(nnz + fill)`，`max_kernel_rows` 默认 4000 → 200000，
  并新增 `max_factor_entries` 作为填充预算（填充是稀疏分解唯一无法事先预测的量）。
  实现中踩到一个结构性 bug 值得记下来：L 的元素若按**位置号**记录，会被后续行主元交换悄悄指到
  错误的行，必须按**原始行号**记录、在求解时查当前的行↔位置映射 —— 两个 LU 测试
  （因子重建 `P·B`、两种求解对拍测试内置的稠密参考）正是抓出它的地方。
  测试内置稠密参考是有意的：随求解器一起发布的"参考"算不上参考；
  实测 `30n20b8`（11591 行）16 秒求到最优，目标值与稠密时代的 `1.5664076455872395` 相差 1.3e-10；
- **presolve（模型化简与解还原）**：`presolve` 包实现空行/列消元、活动范围推出的冗余行判定、
  singleton 行转界、隐式界收紧、固定变量消元（含目标偏移）与 `postsolve` 还原；
  证明不可行或无界时直接返回 `Infeasible` / `Unbounded` 判定，而不是把模型丢给内核。
  正确性论据：150 个随机模型上与内核直接求解**状态与目标值全部一致**，还原解在**原模型**的行与界上
  可行（用独立于化简记账的检查函数测出来）；真实实例上的还原解同样可行。
  实测效果（`--presolve --relax`，目标值与无 presolve 完全一致）：`blend2` 274→186 行
  （79 冗余 + 9 singleton）、353→336 变量（17 固定）、108 个界收紧；`khb05250` 101→100 行、
  1350→1299 变量（51 固定）、2596 个界收紧；`dcmulti` 290→272 行、533 个界收紧；
  `markshare1` 6 个变量固定。
  **已接入公开入口并默认开启**：`SolveOptions::presolve` 默认 true，`solve` / `solve_with` 先化简再求解，
  再把解还原回原变量，并**同时**检查原模型的行、界与目标值三项后才以 `Optimal` 返回，
  不过则返回 `NotSolved` 并附实测违反量；化简能自证不可行/无界时直接返回该判定，不启动内核。
  **整数模型不经化简**：内核的"M5 之前拒绝整数"承诺不能取决于化简是否碰巧定住所有整数变量
  （那也正是非整数固定值会溜进来的地方），含整数变量的模型直接交给内核；
- **有界变量枢轴（bounded-variable pivoting）**：有限上界是**界**而不是行 —— 比值检验两个方向都读
  （基本变量降到 0、或升到自己的上界），非基本变量可以停在它的任一端，进入变量在自己的范围
  先被限住时**翻到另一端且不换基**（无枢轴、无 eta、因子不动）。`fast0507` 的内核行数因此从
  **63490 降到 489**，每次枢轴从约 47.5 ms 降到约 2.4 ms，Phase I 首次跑完。
  实现中踩到两个真 bug（都在"步长归谁算"上）记在"超大实例"一节：`pivot` 用 `xb / rate` 反推步长
  会在基本变量升向上界时得到负步长；零步长的人工驱逐枢轴会拿到无穷上界哨兵当步长。
  回归证据：1000 行口径全清单 16 最优 / 11 跳过 / 0 拒绝，与改动前逐实例一致，用时 162 → 96 秒；
- **增益型定价（greatest improvement，`gain_candidates`，默认 32）**：Dantzig 的检验数是改进的
  **速率**，不是改进本身；实际增益 `|r| · step` 要跑一次比值检验才知道，所以每迭代只测一个有界
  候选集（Dantzig 候选 + 增益候选池 + 轮转窗口）。实测 `fast0507` 在**同一枢轴预算**下：
  20000 次枢轴时内核目标值 165.115（Dantzig）→ **156.778**，45000 次到 **133.032**
  （Dantzig 要 250000 次枢轴才到 160.353）；全清单里 `bienst1` / `bienst2` 因此从
  `iteration-limit` 变成求到最优（各 582 次枢轴），报告口径变成 **18 最优 / 11 跳过 / 0 拒绝**。
  代价是每次枢轴约 2.4 → 14 ms，单次"方向 + 比值检验"评估约 0.36 ms；misc07 的相对偏差从
  约 2e-10 变成约 3.5e-9（顶点不同），重建检查照旧通过；

**待完成**

- **presolve 触发出的内核缺陷（已解除阻塞，根因仍未查清）**：`noswot` 在 presolve 收紧 155 个界之后，
  内核重新分解时报基奇异（同一实例**不带 presolve** 时在同一步分解成功并求到最优 `-43`）。
  已测量的事实：基矩阵在**原始**形态下**没有零行、没有零列**、没有重复基列、没有越界
  （矩阵尺度 21，相关列原始最大元为 1），但高斯消元到该列时其候选元变成**精确 0**
  （保留全部 eta 权重后变为 ~7e-17）——所以这是该基在精确算术下**线性相关 / 近奇异**，
  不是尺度阈值问题。
  **已排除的方向**：一、漂移累积——把 `refactorize_every` 由 500 降到 100 / 50，
  仍在第 200 / 150 次迭代以同样方式失败；二、eta 权重丢弃判据——不丢弃任何权重症状只从
  "精确 0"变成 ~7e-17（该实验已回滚）；三、单靠把奇异阈值改为相对尺度（试过后回滚）。
  **已落地的两道防线**：① **枢轴稳定性校验**（`pivot_relative_tolerance`，默认 1e-8）：
  比值检验选出的主元小于方向最大元的该比例时，先重建逆、再重做比值检验；
  ② **失败恢复**：一次数值失败后从初始基重启用 Bland 规则并缩短重新分解间隔
  （`start_with_bland`），恢复结果同样要过残差自检，仍失败才报原始失败。
  效果：presolved `noswot` 现在求到最优 `-43`（171 次迭代，消息如实标注恢复），
  与无 presolve 的结果一致 —— 两条独立路径给出同一最优值。
  带 presolve 的 300 行口径全量清单：**15 最优 / 17 跳过 / 0 失败 / 1 次恢复**，
  每个重建解都在原模型上可行且**目标值对拍通过**（最大偏差 2e-10，来自不同的最优顶点）；
  **仍未解决的问题**（记为 M3 待完成）：基为什么会变坏没有根因结论，
  候选方向仍是 ① kernel problem 的行列均衡（scaling）、② 真正的基修复
  （单位列替换病态基列后按可行性重入）、③ 退化问题的扰动（perturbation）。
  恢复是"重新走一条路"，不是"修好那条路"；

- **超大实例：一次测量误判、一个已经消掉的行数放大、以及现在的墙**（稀疏 LU 之后逐步暴露）。
  曾经记在这里的结论是"`fast0507` 的 Phase I 停滞，500 次与 4000 次迭代的人工和都是 13"。
  **这个结论是错的，而且错在测量口径上**：
  - 那个 `13` 不是人工和，是 `cmd/parse` 对**没有产出目标的运行**打印 `presolved.objective(0.0)`
    的结果 —— 即化简自身的目标常数（`fast0507` 固定了 8 个变量，贡献 13）。它与迭代次数无关，
    所以"500 和 4000 都是 13"是恒等式，不是现象。实测证据：`--presolve --max-iterations 1`
    印 `solve=iteration-limit obj=13 iters=1`，去掉 `--presolve` 同一运行印 `obj=0`。
    已修：非 `optimal` 的运行不再打印目标（印 `-`），内核把**实测的人工和**写进 Phase I 的
    迭代上限消息里。这条修复是这一轮最有价值的部分 —— 它让下一次不会再花一整轮去调一个不存在的停滞。
  - 真实的 Phase I 行为（presolve 后 63490 行、489 个人工变量、native release、约 0.058 s/枢轴）：

    | 枢轴数 | 200 | 500 | 1000 | 1500 | 2000 | 3000 | 4000 | 5000 | 6000 |
    | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
    | 人工和 | 339.7 | 267.9 | 200.0 | 151.6 | 118.7 | 69.8 | 42.5 | 27.4 | 17.4 |

    它在**稳定下降**，且是几何衰减（约 ×0.78 每 500 枢轴），零步长枢轴只占 2.4%，
    最长的连续无改进只有 6 次 —— 既不是循环，也不是停滞。按该衰减外推，
    要走到 `reduced_cost_tolerance = 1e-9` 的终止判据还需约 4 万次枢轴（≈40 分钟，外推值）。
  - **每次枢轴为什么只拿到一点点**（这是真正的墙）：用一个 512 列的分层抽样量了"实际增益"
    `|rc| · step`。在抽样的 60 次迭代里，**多达 168 列**的增益大于 Dantzig 选中的那一列，
    最好的那一列通常比它大 5–20 倍。例（第 110 次迭代）：Dantzig 选中 `rc = −121.1`、步长
    `0.00632`、增益 `0.76`；抽样里最好的是 `rc = −6`、步长 `1.0`、增益 `6.0` ——
    高 `|rc|` 的列几乎立刻被某条接近紧的约束卡住，而低 `|rc|` 的列能一路走到自己的上界 1。
    也就是说枢轴规则本身让每次枢轴只拿到可用增益的一小部分。
  - **有界变量枢轴已经落地，行数放大消掉了**：不再有"每个有限上界一行"，`fast0507`
    的内核行数从 **63490 降到 489**，而枢轴数随行数走（见上），所以这不是形式上的简化：
    每次枢轴的代价从约 **47.5 ms 降到约 2.4 ms**（实测：45000 次枢轴 177 秒、250000 次 589 秒，
    固定开销约 35 秒），**Phase I 首次跑完**（此前 20000 次上限下还停在人工和约 180）。
    代价是 50v-10 / misc07 / p0201 三个实例一度被报成 unbounded / numerical-failure ——
    根因是人工变量驱逐那条**零步长枢轴**：驱逐时人工变量在 0、进入列应当原地接位（步长 0），
    但有界版本让 `pivot` 自己从方向推步长，而那条行的方向为负，于是它按"升到上界"读了
    人工变量的**无穷上界哨兵**（1e30），一步写出 1e32 的状态。修法是**步长由调用方给出**
    （比值检验第二遍一并返回所选行的步长，驱逐传 0），并让"离开变量落在哪个界"由它**实际落在
    的值**判定，而不是由方向的正负号判定。全清单复核：16 最优 / 11 跳过 / 0 拒绝，
    与改动前逐实例一致（目标值差在 1e-10 相对量级内），全清单用时 162 → 96 秒。
  - **当时的墙是定价，不是行数**（现已落地增益型定价，见下）：Phase II 在 489 行的内核上，
    用 Dantzig 从 20000 次到 60000 次枢轴只把内核目标值从 `165.115` 降到 `164.157`
    （2.4e-5/枢轴），到 250000 次是 `160.353`（约 2e-5/枢轴，几乎线性）。
    作为外部参照：MIPLIB 官方该实例最优值 **174**，松弛问题不可能超过它，
    所以这些值本身是合法的下界方向，但按该速度远不可能收敛。
  - 已经落地的判据修复：防停滞窗口由 `2m + 50` 改成**与 m 无关的固定窗口**
    （`SimplexOptions::stall_window`，默认 500）。旧判据在默认 20000 迭代上限下只能对
    `m < 9975` 生效，在 63490 行的实例上要求 127030 次连续无改进，等于一个不能触发的守卫。
    零回归是**实测**的：1000 行口径全清单（presolve、1200 迭代）每个实例的
    status / 目标值 / 迭代数与上一份报告逐位相同，而全清单里最长连续无改进只有 91 次
    （danoint 的 Phase I），旧判据在任何实例上的阈值都高于它（最小的一个也 ≥ 122），
    所以两个判据在这份清单上都从未触发。
  - 当时的候选杠杆，按已测到的量级排序：① 增益型定价（**已落地**）；② DeVex 定价；
    ③ 对偶单纯形热启动（下面那条）。
- **对偶单纯形热启动（已完成）**：有界变量对偶单纯形（`simplex/dual.mbt`）与热启动入口
  （`SimplexBasis` / `SimplexResult::basis` / `solve_model_with_basis`）。
  原始方法要有可行基再去最优，这个方法要有最优基（对偶可行）再把可行性修回来 —— 界改动不动检验数，
  所以上一个最优基仍然对偶可行，唯一的问题是有基本值落到界外，这正是"分支之后重解"的形状。
  **实测**（native release，收紧一条会切掉当前最优解的界，热启动 / 冷启动的枢轴数）：
  `flugpl` 1/21、`noswot` 6/135、`30n20b8` 14/558、`dcmulti` 32/559、`22433` 49/1008；
  状态与目标值一致，每个热启动结果都带一份**校验器接受**的证书；1000 行口径全清单逐实例零回归。
  基只按形状与对偶可行性受信，任何不符都退回冷启动，所以热启动只能是加速、不能是另一个答案。
  **踩坑**：`new_with_basis` 起初没清掉冷启动基留下的 `is_basic` 标记，不在基里的列被当成基本列，

  抓到它的是 M4 的独立校验器（CLI 探针 `--reoptimize` 打印 `verify=REJECTED(dual signs failed: 0.996)`）。
  现在进基前清标记，并在报最优前**再查一次对偶可行性**，不成立就交冷启动；
- **DeVex / steepest-edge 定价**：仍是候选方向（增益型定价用"实测"换掉了"估计"，

- **待复核（需要一次全清单运行）：已完成**。规模门禁落地后重跑 300 行口径全量清单：
  **32 个实例全覆盖、15 最优、17 跳过、0 数值失败、0 规模拒绝，单进程 native release 用时 83 秒**，

## M4 · 证书与独立校验器（已完成）

**交付物**

- `verify`：独立于求解路径的校验器 —— 原始可行性、对偶可行性、互补松弛、对偶间隙；
- Farkas 不可行证书；无界射线 + 可行起点；
- 证书序列化（JSON）与 CLI `verify` 子命令。

**完成标准与实际结果**

- 故意注入错解的测试必须被拒（含数值上"看起来对"的错解）：**已满足** ——
  `verify/verify_test.mbt` 覆盖"可行但非最优"（拒绝理由是对偶间隙/互补松弛，不是可行性）、
  "偏离可行域一点点"（`4 − 1e-3` 这类）、"看起来像但与点不配套的对偶"、目标值声称错、
  形状不对、错误符号的 Farkas 射线、零射线、以及**故意做错的求解器**给出的答案；
  `simplex/certificate_test.mbt` 再对真实求解结果做**篡改后必须被拒**的三项（符号翻转 / 换成另一个顶点 /
  数值擦边），所以拒绝力不只对构造出来的假证书成立；
- 校验器不复用求解器内部中间量（代码审查可验证）：**已满足** —— `verify/moon.pkg` 只 import
  `core`、`model` 与 `moonlang/core/string`；整包不含任何 `@simplex` 引用，耦合方向由清单文件本身证明；
- 不可行 / 无界实例的证书在独立实现上复核通过：**已满足** —— 内核在三种结论上都产出证书，
  由 `verify` 独立复核：`Optimal` 带行乘子、`Infeasible` 带 Farkas 射线（此前只有一个"实测违反量"，
  那不是证明）、`Unbounded` 带可行起点 + 射线。200 个随机模型语料上三种结论都出现且全部通过；
  真实实例上 `fluglp` / `blend2` / `noswot` / `30n20b8` 的 `--verify` 全部 `accepted`
  （对偶间隙 ~1e-13）。

**实现要点（写在代码里，这里记结论）**

- 乘子约定与弱对偶推导写在包文档（`verify/verify.mbt`）里：`L(x,y) = r·x + D`，
  下界 `= Σⱼ min(rⱼxⱼ) + D`，最优性 = 下界与点上的目标值相等；Farkas 就是同一套式子取 `c = 0`
  且要求严格为正；
- **行乘子的映射是这一步最容易错的地方**：内核在自己的归一化行上工作（`≤` 用松弛、`≥` 用剩余、
  负右端项整行取反），映射回模型的乘子要同时消掉关系带来的符号与整行取反的符号。
  这个因子由 `assemble` 在归一化旁边算出（`row_dual_factor`），而不是在使用处临时推导；
- 踩到一个真 bug 并已修：`box_minimum` 原先按"严格正/负"判断某个检验数是否指向无穷，
  而 `dual_feasibility` 检查带容差 —— 两者阈值不一致，于是 `flugpl` 的一次**正确**求解
  在可行性、对偶可行性、互补松弛全过的情况下被判 `duality gap = 1e300`（"没有有限下界"）。
  现在两处用同一个（带尺度、带容差的）判据；
- CLI：`cmd/parse --verify` 求解后把证书交给校验器并把每项实测值打出来，
  `--certificate <file.json>` 则**只读文件、不求解**地复核（同一文件对另一模型会被拒，退出码 1）。
  证书路径不解 presolve：化简模型的乘子不是原模型的乘子，所以 `--verify` 在模型原样上求解并如实说明。

  "还没有整数点"，而没有最优解可比的界剪不掉任何东西。现在每个分数松弛在被分支之前会先做一次
  **下潜**：走最分数变量较近的整侧、重解、往复，落到的点必然可行（每步过 `@verify`）且必然整数。
  三条启动判据都是量出来的（深度 ≥ 分数变量数、2×分数变量 ≤ `dive_steps`、`dive_attempts` 次上限），
  下潜的松弛计入 `nodes`/`verified` 并受同一预算约束。
  实测（300 节点口径）：有整数点的实例 **1 → 5**（`noswot` -37/下界 -43、`misc07` 3155/下界 1670、
  `p0201` 8095/下界 7555、`khb05250` 115460947/下界 102828749，加已证完的 `22433`），
  报告"点复核"列 1 → 5；`check-mip-objectives.ps1` 0 违反、0 未校验节点。
- **第五轮（已落地）：整数模型接进公开入口**。`Model::solve` / `solve_with` 不再对整数变量返回
  `NotSolved`，而是交给 `mip` 分支定界；`SolveStatus` 增加 `NodeLimit`，`Solution` 增加
  `nodes` / `bound` / `gap`（线性求解下 `bound` = `objective`、`gap` = 0，因为它就是自己的界），
  `SolveOptions` 增加 `max_nodes`（默认与 `mip` 一致）。映射规则一处不含糊：只有搜索自己的
  `Optimal` / `Infeasible` 变成公开的 `Optimal` / `Infeasible`；预算到顶变成 `NodeLimit`
  （`values` 是**可行但未证明最优**的整数点）；**松弛无界、证书被拒、模型非法一律 `NotSolved`**
  并带搜索自己的原话 —— 它们各自都没有证明任何结论。整数模型依旧不做化简。
  测试：整数模型经公开入口求到**整数最优**而不是松弛值（松弛 73/6、答案 10 且点整）、
  节点预算报成 `NodeLimit` 而不是最优性主张、无整数点证成 `Infeasible`、松弛无界不报成模型无界；
  `cmd/main` 增两段演示（整数解 + 一次预算到顶）。
- **第六轮（已落地）：下潜的步数预算按实测放大**。`2×分数变量` 只是"这一步至少要走多久"的**下界**
  （一步重解后可能让另一个变量变成分数），所以每次启动的预算改为 `dive_steps`，默认 30 → 60。
  实测（300 节点口径）有整数点的实例 **5 → 8**（新增 `markshare1` 345、`pk1` 52、`markshare2` 252）。
  诊断同时确认了两件事：`flugpl` 的"两个方向都不可行"是**已证明的死区**而不是卡住（所以不换变量是对的），
  `dcmulti`/`rout`/`50v-10` 是启动判据①不满足（从未启动）。
- **第七轮（实测后回退）：可回溯下潜没有收益**。把下潜改成带决策栈的 DFS（遇死区回退一层、试另一侧）
  实现完成并通过白盒测试，但同一口径 300 节点下 13 个到预算的实例里 12 个逐位相同、8 个整数点一个没多，
  而 `flugpl` 的"仍在开"从 167 降到 119（走法吃了更多预算，界略好）；把 `dive_steps` 提到 120 仍无新整数点，
  树的工作量反而塌陷（仍在开 43 / 55 / 61）。结论：**瓶颈是预算总量，不是走法彻底程度**，
  按"没测出收益的改动不留"回退（详见 `CHANGELOG.md`）。
  **因此"原始启发式"这一族到此为止**：下一步的杠杆改为割平面与分支规则。
- **第八轮（实测后回退）：伪成本分支把"界"的信号当成了"找整数点"的信号**。把每个子节点的目标值
  相对父节点界的退化按变量/方向做单位分数化平均，取两侧预测乘积最大的变量分支（无历史时回落最分数）。
  它确实换来了更好的整数点（`misc07` 3155→3145、`p0201` 8095→7795、`khb05250` 115460947→112274426、
  `pk1` 52→47、`dcmulti` 首次拿到 189389.4），但**代价是灾难性的**：`22433` 从"49 节点证到最优"
  变成"20000 节点无整数点"，`flugpl` 从"12411 节点证到最优"变成"20000 节点无整数点"，
  且 5 个实例的界变差（`gt2` 13862.9 → 18382.4）。原因是**信号方向**：目标值退化是对偶（界）的信号，
  用它分支等于系统偏好"离当前点更远"的方向，因而把"松弛几乎整"的实例推离整数点。
  另外它在 `misc07` 上换来的一条新轨迹**撞上了仍然活着的已知缺陷**（Farkas 证书，
  节点 380 / 深度 14 / 预算无关，见 `CHANGELOG.md` 与本文件下面的"已知缺陷"一节）。
  按"没测出收益不留"回退（工作树 == `942d922`）。
- **第九轮（已落地）：追那条"被拒的 Farkas 证书"，发现的是"假不可行"**。外部求解器说 `misc07`
  节点 380 **可行**（最优 1677），所以内核的 `Infeasible` 判定错了、证书被拒只是症状。
  根因：Phase I 的判据量的是 `state.values()`，而基本值在 907 次枢轴后已漂移到不满足 `B x_B = b`
  （人工和只有 1e-8 说明按人工口径这个点是可行的，而行残差量出 1.45e-6 —— 量的是算术不是模型）。
  修法沿用 `finish_optimal` 的先例：**判定前先重建因子再量**，重建失败就报 `NumericalFailure`。
  实测：复现轨迹不再被拒、真不可行照旧判出（`scaled=0.297` 的节点仍是 `Infeasible`）、
  基线 300 节点 13 例 **0 拒签**、报告按新代码重新生成。
- **已知缺陷（仍未验证，但不再阻塞）**：**Farkas 射线的构造本身**（"Phase I 的对偶解即射线"）
  仍然没有证据 —— 第九轮修掉的是那个可复现的被拒案例（它是假不可行），不是这条构造。
  能说的是：校验器每次独立复核，没有证据的射线不可能通过。要给它证据，需要一条**真的不可行**且
  Phase I 退化到"对偶解恰好边界"的用例，或改成从 Phase I 状态显式导出满足符号约定的射线
  （且**必须自带自检**，第二轮删掉 `farkas_ray` 系列正是因为它没有自检）。
- **第十轮（已落地）：割平面 —— 先设计，再动手**。割是本项目里唯一会"静默出错"的部件：一条无效割会
  从它落地的节点起把整数点（可能是真最优）删掉，而**现有每条防线都会继续点头**（后续松弛被正确求解、
  证书拿带割的模型去校验、报告的点复核也拿带割的模型量）。所以这一轮的产出先是**有效性如何被独立检验**：
  割 = 一行 + **它由哪一行舍入而来**的证明（模型行的组合 `r = Σyᵢaᵢ`、`β = Σyᵢbᵢ`，基变量为整数变量时
  经典舍入成立），`verify/cuts.mbt` 的 `verify_cut` 把这一行**重算一遍**，并逐条量：组合重现自己声称的行
  （`r_B = 1` 且右端项一致）、基变量是整数、其余变量都能从**有限界**写成非负变量、小数部分离 0/1 足够远
  （判据是 `combination_noise`，即产生这一行的算术有多大）、**割本身大于产生它的算术**、以及与交上来的行
  逐项相同；拒了就停成 `Unverified`，绝不"跳过继续"。落地形态：`verify/cuts.mbt`（新）、
  `simplex/cuts.mbt`（新，表行 → 模型行乘子，并在 `assemble` 里显式记下行归一化符号 `row_sign`）、
  `mip/cuts.mbt`（新，选行/选移位/只保留当前点违背的割/每轮上限）、`mip/search.mbt` 的根节点割轮次、
  `MipOptions::cut_rounds`、`MipResult::cuts`、CLI `--cut-rounds`、报告 `cuts` 列。
  证据：151 → **160 个测试**（手算例、**故意做错的割必须被拒**并且那条错割确实砍掉一个可行整点、
  四种缺条件的见证被拒、**300 轮随机小模型穷举**所有可行整点复核、搜索侧"开割关割答案一致"与
  "做坏的割让运行停在 `Unverified` 且 `cuts = 0`"）；实测 14 个实例逐项前后对比 **10 个变好**
  （6 个界更紧、5 个当前解更好、`gt2` 首次拿到整数点、`khb05250` 触到官方最优值 106940226、
  `22433` 证明最优 59 → 33 个节点、`p0201` gap 1437.5 → 747.5），2 个当前解在预算内变差。
  修掉一条真缺陷：**一轮割只有在重解的结论不变差时才保留**（`noswot` 上 20 条割让根重解跑不完，
  原始写法让整个运行在 3 个松弛后结束、界为 0，比不加割严格更差）。
  报告已重新生成：32 实例 1 最优 / 14 节点预算 / 17 跳过 / 0 被拒证书 / 3932 松弛过校验 /
  **256 条割过 `verify_cut`** / 9 个点通过独立复核。限度：**只在根节点割**；6 个实例仍拿不到整数点
  （界都更紧但没踩到整点）。
- **尚未完成（下一步）**：
  1. **节点上的割与割池**：现在割只落在根模型上；节点割需要处理"节点 = 父 + 一条界"的形状与热启动
     （割会改变问题形状，重解只能冷启动），换来的是更深处的界；
  2. **更强的割族**：现在只有对**一行**的舍入；MIR（多行聚合）、补割（complemented slack）与
     "只在当前点违背且足够强的割"的筛选，是把 6 个无点实例推下去的下一条路；
  3. cutoff 传播，以及把"已证最优"的覆盖面从三个实例扩到标记为"小规模"的一整批；
  4. 把第三轮新增自检的开销换回来（LP 全清单总枢轴 +27%、`fast0507` 同预算下 160.01 → 166.08）：
     方向自检每迭代一趟 `O(nnz(A))`，值得改成更省的判据（例如只在主元可疑时量）；
     第九轮又给 Phase I 过渡加了一次重建因子（每次求解一次），值得和这条一起量；
     另外 `bench/solve-report.md` 仍是 `315107f` 生成的（已过期），做性能测量时要重跑。

## 明确不做（非目标）

以下内容在可预见版本内不做，并会在 README 与文档中明确标注，避免夸大承诺：

- 非线性 / 凸优化（NLP）、半定规划；
- 随机规划与分解算法（Benders、Lagrangian 松弛）；
- 并行 / 多线程求解；
- 网络单纯形专用高速路径（不追求大规模网络流实例的顶尖性能）；
- MPS 的极小众扩展（完整 `MARKER` / `SOS` 语义）与 CPLEX LP 格式的全部扩展；
- Python / JS 绑定（保持纯 MoonBit、零 FFI）。

## 规模承诺的措辞

不写“目标万级约束/变量”。对外只报告**实测**：以 Netlib 实例规模分布为参照，
列出“≤ 2 000 行实例 X/Y 解到已知最优”，更大实例逐条给出结果与原因。
